# ANTLR Parser Compact Strategy & Optimization Roadmap

This document defines the architectural analysis, technical rationale, and phased implementation roadmap for slimming down the generated Microsoft T-SQL ANTLR4 parser (`pkg/proc/parser/antlr/`) in LionSQL.

---

## 1. Executive Summary & Current Status

LionSQL enforces a **Dual-Parser Architecture** (ADR-004, `GEMINI.md` Section 2) consisting of:
1. **Primary Fast-Path (Native Pratt / Recursive Descent Parser)**:
   - Location: `pkg/proc/lexer.go`, `pkg/proc/parser.go`
   - Size: ~3,120 lines of hand-crafted Go code
   - Latency: Sub-microsecond (0.1µs ~ 0.5µs), zero heap allocations on hot paths
   - Handles: 99%+ of queries, standard DDL, DML, and core procedure control flow
2. **Secondary Fallback (Official Microsoft T-SQL ANTLR4 Parser)**:
   - Location: `pkg/proc/parser/antlr/`
   - Grammar: `grammar/TSqlParser.g4` (6,307 lines), `grammar/TSqlLexer.g4` (1,293 lines)
   - Size: **267,067 lines of generated Go code** (8.2MB `tsql_parser.go` alone)
   - Purpose: Automatic runtime fallback for advanced, vendor-specific, or legacy MSSQL syntax (`WITH RECOMPILE`, `WITH ENCRYPTION`, schema prefixes, vendor options)

While the ANTLR fallback provides full Microsoft T-SQL compatibility, its **267,000 lines represent over 70% of the entire LionSQL repository**, increasing compilation times, inflating binary size, and complicating IDE indexing.

```
+-------------------------------------------------------------------------------+
|                       LionSQL Source Code Footprint                            |
+-------------------------------------------------------------------------------+
| Pure Handwritten Go Code (Engine, Storage, Wire, VM, Tests):  104,675 lines  |
| Generated ANTLR Fallback Parser (pkg/proc/parser/antlr/):     267,067 lines  |
| Technical Documentation & Manuals (doc/*.md):                  10,924 lines  |
+-------------------------------------------------------------------------------+
```

---

## 2. Root Cause Analysis: Why is the Generated Parser So Huge?

### 2.1. Complete 30-Year MSSQL Enterprise Syntax Inclusion
The ANTLR grammar source (`grammar/TSqlParser.g4`) is an exhaustive specification covering every Microsoft SQL Server feature introduced over three decades:
* **Service Broker**: `CREATE QUEUE`, `CREATE MESSAGE TYPE`, `CREATE CONTRACT`, `SEND ON CONVERSATION`, `RECEIVE`, `END CONVERSATION`
* **Resource Governor**: `CREATE RESOURCE POOL`, `CREATE WORKLOAD GROUP`, `ALTER RESOURCE GOVERNOR`
* **Replication**: `sp_addpublication`, `sp_addsubscription`, `CREATE ENDPOINT`
* **Full-Text Search**: `CREATE FULLTEXT CATALOG`, `CREATE FULLTEXT INDEX`, `CONTAINS`, `FREETEXT`
* **Extended Events**: `CREATE EVENT SESSION`, `ALTER EVENT SESSION`, `DROP EVENT SESSION`
* **External PolyBase & Fabric**: `CREATE EXTERNAL DATA SOURCE`, `CREATE EXTERNAL TABLE`
* **Spatial & XML Methods**: Deep geometric and XML schema syntax specifications
* **Database Mirroring & Availability Groups**: `ALTER AVAILABILITY GROUP`, `CREATE ENDPOINT FOR DATABASE_MIRRORING`

None of these enterprise subsystems exist or are planned in LionSQL's embedded single-node architecture (`GEMINI.md` Section 5 & 6). Yet the parser state machines (ATN) for these hundreds of unused rules are generated into Go code.

### 2.2. ANTLR4 Go Target Code Expansion
The ANTLR4 Go code generator expands each grammar rule into:
1. `Context` struct and interface types.
2. Getter methods for every token and child rule.
3. Listener (`Enter*`, `Exit*`) and Visitor (`Visit*`) interface contracts and default implementations.
4. **Massive ATN Transition Tables**: Serialized integer array literals (`_serializedATN`) embedded directly in source code spanning tens of thousands of lines.

## 3. Phased Slimming Strategy

The optimization strategy is divided into four sequential, low-risk phases:

```
[ Phase 1: Listener Pruning ] ──► [ Phase 2: Grammar Subsetting ] ──► [ Phase 3: ATN Packing ] ──► [ Phase 4: Native Independence ]
       (-10,000 lines)                   (-180,000 lines)                    (-40,000 lines)                   (Zero ANTLR)
```

### Phase 1: Unused Listener Elimination (`-no-listener`)
* **Objective**: Remove dead code that is generated by default but never invoked by LionSQL.
* **Technical Detail**:
  - `pkg/proc/parser/antlr/ast_builder.go` relies strictly on the **Visitor Pattern** (`BaseTSqlParserVisitor`, `tree.Accept(b)`).
  - The ANTLR CLI generates listener files by default unless `-no-listener` is passed.
  - Files to eliminate:
    - `tsqlparser_listener.go` (4,893 lines)
    - `tsqlparser_base_listener.go` (5,165 lines)
* **Expected Savings**: **~10,058 lines eliminated immediately** with zero behavioral changes.
* **CLI Command**:
  ```bash
  antlr4 -Dlanguage=Go -no-listener -visitor -package parser grammar/TSqlLexer.g4 grammar/TSqlParser.g4
  ```

---

### Phase 2: LionSQL Target Grammar Pruning (`TSqlParser_compact.g4`)
* **Objective**: Create a focused, slimmed-down T-SQL grammar that retains 100% of the syntax LionSQL supports while pruning irrelevant enterprise subsystem rules.
* **Rules to Retain (100% Preserved)**:
  - Procedural Control Flow: `CREATE/ALTER PROCEDURE`, `CREATE/ALTER FUNCTION`, `IF/ELSE`, `WHILE`, `BEGIN/END`, `TRY/CATCH`, `RETURN`
  - Variable Handling: `DECLARE @var`, `SET @var`, `SELECT @var = expr`
  - DDL: `CREATE/ALTER/DROP TABLE`, `CREATE/ALTER/DROP VIEW`, `CREATE/ALTER/DROP INDEX`
  - Core DML: `SELECT`, `INSERT`, `UPDATE`, `DELETE`, `MERGE`
  - Expressions, Operators, Built-in Functions, and T-SQL Clauses (`WITH RECOMPILE`, `WITH ENCRYPTION`, schema qualifiers, bracket escapes `[dbo].[tbl]`)
* **Rules to Prune (Safe Deletion)**:
  - `service_broker_statements`
  - `resource_governor_statements`
  - `replication_statements`
  - `fulltext_statements`
  - `extended_events_statements`
  - `polybase_external_statements`
  - `availability_group_statements`
* **Expected Savings**:
  - Grammar lines: 6,307 ➔ ~1,800 lines (71% reduction)
  - Generated Go code: 242,425 lines ➔ **~45,000 lines (~80% reduction)**
* **Verification**: All regression procedure test cases in `pkg/proc/runtime/regression_test.go` and `pkg/proc/parser/antlr/antlr_test.go` must pass 100%.

---

### Phase 3: ATN State Table Packing / Compression
* **Objective**: Compress the remaining serialized ATN tables (`_serializedATN`) in `tsql_parser.go`.
* **Technical Detail**:
  - In the ANTLR Go target, integer slice literals (`[]int{1, 2, 3, ...}`) consume millions of characters across source files.
  - A post-processing script can encode the raw ATN byte stream into a Base64/Gzip-compressed string literal, unpacking it during package `init()`.
* **Expected Savings**: Additional 30~40% reduction in generated file size and compilation AST memory footprint.

---

### Phase 4: Long-Term Native Pratt Parser Expansion (Zero-ANTLR Target)
* **Objective**: Gradually expand the Native Pratt Parser (`pkg/proc/parser.go`) to achieve 99.99% T-SQL syntax coverage, enabling the complete retirement and removal of the ANTLR fallback subsystem.
* **Technical Rationale**:
  - The Native Pratt Parser is pure Go, sub-microsecond, and weighs only ~3,120 lines.
  - Areas currently triggering ANTLR fallback:
    - Advanced procedure signature options: `WITH ENCRYPTION`, `WITH RECOMPILE`, `WITH EXECUTE AS ...`
    - Non-standard parameter defaults and XML/Table types in procedure parameters.
  - By porting these remaining edge cases into `pkg/proc/parser.go`, the entire `pkg/proc/parser/antlr/` package (and its `github.com/antlr4-go/antlr/v4` external module dependency) can be permanently deprecated and removed.
* **Ultimate Outcome**:
  - **Zero third-party parser runtime dependencies**.
  - **267,000 lines deleted from repository** (clean compliance with Golden Rule 15: Radical KISS & Deletion-First).
  - Instant compilation and type checking across the entire project.

## 4. Verification & Safety Guardrails

Any modification to grammar files or generated code must adhere strictly to the **3-Stage Pipeline**:
1. **Compilation**: Complete rebuild of `bin/server`, `bin/bench`, and `bin/tpcc-runtime` (`go build -tags wiredtiger`).
2. **Regression Parity**:
   ```bash
   go test -tags wiredtiger -v -run TestProcedureRegression pkg/proc/runtime/...
   go test -tags wiredtiger -v -run TestANTLR pkg/proc/parser/antlr/...
   ```
3. **Full Race Verification**:
   ```bash
   go test -tags wiredtiger -count=1 -race ./...
   ```
   Must achieve 100% PASS with 0 data races.
