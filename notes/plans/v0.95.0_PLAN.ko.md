## 1. 개요 및 마일스톤 목표

LionSQL은 `v0.94.0`을 통해 Windows 단일 바이너리 내장 DLL 자가 추출, 기본 스토리지 엔진의 WiredTiger 전 플랫폼 일원화, T-SQL 저장 프로시저 1,289개 오라클 100% 무결점 통과를 달성하였습니다.

`v0.95.0`은 공식 1.0 LTS(GA) 직전의 최종 프리-릴리스(Release Candidate / RC1)로서, 실무 생태계 도구 연동과 극한 부하 시의 메모리/스트리밍 병목을 해소하기 위한 **4대 핵심 완성 과제**를 완수하는 데 집중합니다:

1. **[Ecosystem / Wire]**:
   - `FEAT-WIRE-TDS-BCP-BULK-LOAD-1`: TDS 0x07 BCP (Bulk Load) 대량 데이터 적재 스트리밍 지원
   - `FEAT-WIRE-PG-REMOTE-CANCEL-1`: PGWire 외부 TCP CancelRequest (80877102) 백엔드 쿼리 캔슬 연동
2. **[Storage & DDL]**:
   - `FEAT-ALTER-COLUMN-ONLINE-EXPANSION-1`: `ALTER TABLE ALTER COLUMN` 가변길이 컬럼(`VARCHAR(N)`) 온라인 $O(1)$ 확장 지원
3. **[Execution / Perf]**:
   - `ARCH-UNIFIED-TUPLE-PROTOCOL-1`: 타입 타워 3중화 해소: `storage.Row` 기반 Positional Tuple 결과셋 및 Wire 직결
4. **[Durability]**:
   - `DURA-SOAK-1`: WiredTiger 기반 24시간 장기 스트레스 소크 및 무작위 `kill -9` 복구 검증

## 2. 과제별 세부 설계 및 실행 계획

### 과제 1. Wire 프로토콜 실무 완성도 제고
- **과제 ID**: `FEAT-WIRE-TDS-BCP-BULK-LOAD-1`, `FEAT-WIRE-PG-REMOTE-CANCEL-1`
- **도메인**: Wire Protocol (`pkg/wire`, `pkg/wire/tds`)

#### 1.1 TDS 0x07 BCP (Bulk Load Protocol)
- **배경**: `bcp.exe`, .NET `SqlBulkCopy`, SSMS 대량 가져오기 마법사는 일반 `INSERT`가 아닌 TDS 패킷 타입 `0x07` (`PacketBulkLoad`)을 사용하여 메타데이터와 대량 튜플 스트림을 전송함. 현재 LionSQL은 `default:`로 빠져 단순 `DONE`만 반환함.
- **설계**:
  1. `pkg/wire/tds/server.go` 패킷 수신 루프에 `case PacketBulkLoad:` 핸들러 추가 (`handleBulkLoad`).
  2. BCP 컬럼 메타데이터(Column Count, Data Types, Nullability) 파싱.
  3. 인입되는 바이너리 행 스트림을 디코딩하여 내부 `storage.Table.BatchInsert(rows)`로 직결.
  4. 완료 시 처리된 행 수(`DoneRowCount`)와 함께 `TokenDone` 반환.
- **테스트**: `test/corpora/bcp_test.go` 및 Go mssql-driver / Python pymssql 기반 벌크 복사 E2E 테스트.

#### 1.2 PGWire 외부 TCP CancelRequest (80877102)
- **배경**: PostgreSQL 클라이언트(`psql`, DBeaver, JDBC, pgx)는 쿼리 실행 중 `Ctrl+C`나 [Cancel] 클릭 시 현재 커넥션이 아닌 새 TCP 연결을 열어 특수 매직 넘버(`80877102`), 타깃 세션 PID, Secret Key를 전송함.
- **설계**:
  1. `pkg/wire/server.go`에서 시작 패킷이 `CancelRequest`일 경우 인증 핸드셰이크를 건너뛰고 세션 레지스트리에서 타깃 세션 검색.
  2. 타깃 세션의 활성 쿼리 `context.CancelFunc` 호출.
  3. TCP 연결 즉시 종료 (PostgreSQL Wire V3 표준 동작).
- **테스트**: `psql` 환경에서 긴 쿼리 실행 중 `SIGINT` 외부 취소 연동 검증.

### 과제 2. `ALTER TABLE ALTER COLUMN` 가변길이 온라인 확장
- **과제 ID**: `FEAT-ALTER-COLUMN-ONLINE-EXPANSION-1`
- **도메인**: Storage & DDL (`pkg/engine`, `pkg/storage`, `pkg/catalog`)

- **배경**:
  - 운영 중 가장 흔히 발생하는 DDL은 `VARCHAR(50)`을 `VARCHAR(100)`으로 늘리는 가변길이 확장임.
  - LionSQL V2 바이너리 튜플 코덱(Invariant 13)은 가변길이 컬럼을 `[len(2B)][raw bytes]` 형태로 연속 기록하므로, 최대 길이 상한 확장(`50 ➔ 100`)은 디스크 상의 기존 데이터 튜플을 재배치하거나 재인코딩할 필요가 없음.
- **설계**:
  1. **파서 확장**: Pratt 및 ANTLR4에서 `ALTER TABLE <tbl> ALTER COLUMN <col> <type>` 구문 AST 파싱 지원.
  2. **유효성 검사**:
     - 컬럼 존재 여부 확인.
     - 동일 데이터 타입 내에서의 확장만 허용 (`VARCHAR(M) ➔ VARCHAR(N)`, 단 $N \ge M$).
     - 축소(Truncation) 시도 시 기존 데이터 손실 위험이 있으므로 Fail-Closed 차단.
  3. **카탈로그 즉시 갱신 ($O(1)$)**:
     - 테이블의 `ColumnDef.Length` 또는 `ColumnDef.Precision`을 메모리 및 `catalog.json`에 원자적으로 반영.
     - 기존 B-Tree 파일에 대한 물리 rewrite 0건, 배타적 락 지연 최소화.
- **테스트**: `pkg/engine/alter_column_test.go`에서 확장 후 이전 데이터 조회 및 확장된 크기 데이터 신규 삽입 검증.

### 과제 3. 타입 타워 3중화 해소 및 `storage.Row` 직결
- **과제 ID**: `ARCH-UNIFIED-TUPLE-PROTOCOL-1`
- **도메인**: Architecture & Performance (`pkg/engine`, `pkg/proc/runtime`, `pkg/wire`)

- **배경**:
  - 현재 쿼리 실행 경로는 `storage.Row` ➔ `engine.Record` (map[string]any) ➔ `QueryResult.Rows` ➔ Wire 인코딩 단계에서 맵 할당 및 해시 조회가 중복 발생함.
  - 수만~수십만 행 SELECT 시 대량의 힙 할당과 GC 압력이 집중됨.
- **설계**:
  1. `QueryResult` 구조체에 포지셔널 슬라이스 `TupleRows []storage.Row` 추가.
  2. Volcano 및 VDBE 실행기가 컬럼 이름 매핑을 헤더(`Columns []string`)에 1회만 고정하고, 각 데이터 행은 `storage.Row` 순수 값 슬라이스로 전달.
  3. Wire 프로토콜 인코더(`pkg/wire/row_encode.go`, `pkg/wire/tds/row.go`)가 맵 검색 없이 인덱스 기반 포지셔널 디코딩으로 소켓 버퍼에 직결.
  4. REST API 등 JSON 변환이 필요한 경우에만 선택적(Lazy) 맵 구체화 수행.
- **테스트**: 기존 SQLLogicTest 409k 및 1,289 T-SQL 스위트 100% 호환성 유지 및 벤치마크 메모리 할당 40% 이상 절감 검증.

### 과제 4. 1.0 LTS 사전 내구성 검증 게이트 통과
- **과제 ID**: `DURA-SOAK-1`
- **도메인**: Durability & Reliability (`cmd/soaktest`, `cmd/crashtest`)

- **배경**: 1.0 LTS 정식 배포의 전제 조건인 24시간 연속 가동 안정성과 크래시 복구 내구성을 최종 확증함.
- **실행 계획**:
  1. **24시간 장기 소크 (`cmd/soaktest`)**:
     - 8개 동시 고루틴 트랜잭션 워커 (계좌 이체, 잔액 불변성 검증).
     - WiredTiger 엔진 대상 24시간 연속 구동.
     - 메모리 누수(RSS 안정성), 고루틴 누수(Goroutine 개수 불변), 파일 디스크립터(FD 누수 0) 자동 판정.
  2. **1,000 라운드 무작위 사살 복구 (`cmd/crashtest`)**:
     - 트랜잭션 쓰기 도중 무작위 `kill -9` 후 재시동 복구.
     - WAL / WiredTiger 트랜잭션 로그를 통한 100% 원자적 복구 및 데이터 오손 0건 입증.
